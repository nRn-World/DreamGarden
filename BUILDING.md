# Building Dream Garden

## Requirements

- Node.js 20+ or Bun 1.2+
- A modern browser for manual testing
- For native packages: Android Studio + JDK 21, and Xcode 16+ for iOS

## Install and run

```bash
bun install
bun run dev
```

The dev server listens on <http://127.0.0.1:5173>. It is bound to loopback on purpose.

## Checks

```bash
bun run typecheck   # tsc --noEmit
bun run test        # vitest run — 50 tests
bun run build       # typecheck + production build + service worker
bun run preview     # serve dist/ on 127.0.0.1:4173
```

The build must remain warning-free. The service worker is generated by `vite-plugin-pwa` in
`generateSW` mode and precaches the shell.

## Regenerating icons

`public/icons/icon.svg` is the source. After editing it:

```bash
node scripts/generate-icons.mjs
```

This writes 192/512/maskable/apple-touch/favicon PNGs with `sharp`. The generated images are
committed so a clean clone builds without running the script.

## Hosting the PWA

Upload the contents of `dist/` to any HTTPS static host (Cloudflare Pages, Netlify, GitHub Pages,
S3 + CloudFront, nginx). Requirements:

- serve `index.html` as the fallback for unknown paths;
- serve `.webmanifest` as `application/manifest+json`;
- do not cache `sw.js` for long periods;
- HTTPS is required for installability and service workers (localhost is exempt).

If hosted under a subpath, change `base`, `start_url` and `scope` in `vite.config.ts` together.

## Wrapping for Google Play and the App Store

The recommended path is Capacitor, which wraps the same `dist/` in a native container and gives
access to store billing and AdMob if you enable them.

```bash
bun add @capacitor/core
bun add -d @capacitor/cli
bunx cap init "Dream Garden" com.nrnworld.dreamgarden --web-dir=dist
bunx cap add android
bunx cap add ios          # macOS only
bun run build
bunx cap sync
bunx cap open android     # Android Studio
bunx cap open ios         # Xcode
```

Then:

1. Set the app id exactly to `com.nrnworld.dreamgarden`.
2. Replace the launch/splash assets with `public/icons/icon-512.png` and the brand colours
   `#07050f` / `#a9f0cf`.
3. Build a signed **AAB** (`Build → Generate Signed Bundle`) for Play.
4. Build an archive in Xcode and upload to App Store Connect.
5. Handle the Android hardware back button (close sheet → previous screen → exit) and the iOS safe
   areas. The web layout already respects safe-area env variables.
6. Keep the game fully offline: the service worker precache works inside the WebView as well.

See [docs/ANDROID_PACKAGING.md](docs/ANDROID_PACKAGING.md) for the full Play checklist and
[HUMAN_ACTIONS.md](HUMAN_ACTIONS.md) for credentials and legal steps.

## Repository hygiene

- Never commit keystores, `.env`, ad unit IDs or store credentials.
- The build contains no secret. Anything shipped to a device is public.
- Generated folders (`dist/`, `node_modules/`) are not source of truth.

## Troubleshooting

| Symptom | Cause / fix |
| --- | --- |
| Blank page after deploy | Wrong base path; check `base` and the host's fallback route |
| Old version after deploy | Service worker cache; `registerType: 'autoUpdate'` is set, reload twice |
| No install prompt | Needs HTTPS, a valid manifest and icons; some browsers only show it in the menu |
| Arabic layout looks left-aligned | Ensure `<html dir>` is set by the store; it is set on locale change and on boot |
| Save not persisting | Private mode or blocked storage; the game warns and runs in memory |
